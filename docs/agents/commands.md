# Commands

`tartci` is a bash dispatcher at the repository root. On an installed host it
is `~/.local/bin/tartci`, a shim into the installed support generation. Every
command below is listed in the dispatcher's header comment.

Effect column: **read** changes nothing; **plan** reads and prints what it
would do; **write** changes host state.

## Inspect (read)

| command | effect | notes |
|---|---|---|
| `tartci doctor` | read | prerequisites, stores, Shipyard GitHub auth |
| `tartci doctor fleet [--json] [--no-census]` | read | executed generation, drain capability, runner census across repo and org scopes. Exit 0 healthy, 1 problem, 2 undetermined. Reason codes are in `scripts/fleet_reasons.json` |
| `tartci doctor --reap --json` | read | stale owned VM, overlay and runner residue. Exit 0 healthy, 1 stale or wedged, 2 unreadable |
| `tartci doctor build-disagreement [--json]` | read | cross-host compile or link disagreement (cache poisoning). Off by default |
| `tartci version [--json]` | read | the commit this copy runs: an installed generation's support manifest, or a checkout's HEAD (and whether it has uncommitted changes). Exit 1 when neither says |
| `tartci status --json` | read | providers, capacity, role, janitor install state |
| `tartci host-profile [--json]` | read | derived role and budget (`PULP_BUILD_JOBS`, `PULP_BUILD_MEM_BUDGET_MB`) |
| `tartci host-profile --delivery [--json]` | read | how code reaches each lane, and staleness |
| `tartci governor show\|explain\|fleet\|keys` | read | the per-host governor config |
| `tartci leases status` | read | host lease store |
| `tartci leases stats` | read | host lease store (`events.jsonl`) |
| `tartci pool status [--json] [--require-ready] [--require-serving]` | read | admission state and participation |
| `tartci pool status --usage [--range 24h] [--json]` | read | slot occupancy, idle-with-demand, discards, per-phase VM time |
| `tartci fleet capacity --repo OWNER/REPO --target LABEL [--profile ABS] [--json]` | read | embedded-evidence, profile-bound observation receipt (`auth_method=untrusted_local`); unknown state fails closed |
| `tartci pool log --status` | read | bounded history of pool status |
| `tartci observe macos [--json] [--no-guest] [--runner NAME]` | read | live macOS VM jobs. Exit 0 trustworthy, 3 coverage shortfall (`BLIND:` or `UNKNOWN:`) |
| `tartci profile list\|show\|explain\|plan` | read | routing profiles in `profiles/` |
| `tartci runtime summary\|recent\|export` | read | runtime records when `TARTCI_RUNTIME_MEASURE=1` |
| `tartci metrics report\|dashboard [file]` | read | build metrics table or HTML |
| `tartci timings` | read | per-job `timing.tsv` summary |
| `tartci goldens list`, `tartci goldens doctor` | read | canonical golden, drift, receipts |
| `tartci ccache scan` | read | counts suspect direct-mode manifests |
| `tartci hooks print` | read | prints agent hook settings; never writes them |
| `tartci launchd status` | read | serve LaunchAgent state |
| `tartci fleet-macos tool-freshness [--json]` | read | Shipyard and pulp CLI versus latest release |
| `tartci doctor runner-age [--json]` | read | Actions runner each golden's VMs run: warn when two minor versions behind, fail when refused by GitHub; exit 1 on fail |
| `tartci update --status [--json]` | read | one line: installed commit, skew, the live update step and how long it has run, last result |
| `tartci update --wait [--json] [--timeout S]` | read | silent until this host's running update ends, then one line; exit 0 succeeded, 3 refused, 4 failed, 124 timed out. Run it in the background to be woken |
| `tartci update [--yes]` | apply | update this host (same engine as `fleet-macos self-update --apply`): asks y/N on a terminal, never applies without one unless `--yes`; prints one line and keeps the full output in `~/.tartci/state/self-update/last-update-output.log` |
| `tartci fleet-macos self-update --plan` | plan | default mode; steps 1 to 4 of the update, read-only |
| `tartci pool <on\|drain\|off> --plan` | plan | prints the transition, writes nothing |
| `tartci launchd reload <label> --dry-run` | plan | prints the plan or `REFUSE` (exit 0 or 3) |
| `tartci reclaim`, `tartci image-prune`, `tartci retention` | plan | without `--fix` / `--apply` |

## Change host state (write)

| command | effect | refuses when |
|---|---|---|
| `tartci setup` | installs Tart (requires macOS 15 or later for a fresh install), QEMU, sshpass, jq, gh; creates stores under `TARTCI_HOME`; derives the host role; installs the disk reclaimer and support agents | Homebrew missing |
| `tartci pool drain` | writes participation 0 and pool state `draining`; disables restart of receipt-owned runner agents; the running job finishes | capacity floor (last host serving a required label); a persistent Actions runner without an authoritative idle receipt (exits nonzero, stays pending) |
| `tartci pool undrain` | exact inverse of a drain: re-enables the agents and reopens admission | pool is not `draining` |
| `tartci pool off [--now]` | closes admission and boots out owned agents immediately | capacity floor; a lane is mid-job (exit 12) unless `--now` |
| `tartci pool on` | restores exactly the services the fleet profile receipt names | receipt rejected |
| `tartci pool repair-lock` | removes an orphaned pool transition lock | admission open, owner alive, or a runner or VM is active (exit 5) |
| `tartci launchd reload <label>` | full bootout and bootstrap; re-reads the plist | the lane is mid-job (exit 3) unless `--allow-mid-job` |
| `tartci launchd heal` | heals a wedged serve LaunchAgent | |
| `tartci governor set K=V`, `unset K` | edits `~/.config/tartci/governor.toml` | |
| `tartci leases acquire\|release\|heartbeat\|reap` | edits the lease store | |
| `tartci serve <os> [--once\|--loop]` | runs the serving loop: boots a VM per matching queued job | lease denied, pool not admitting, JIT denial receipt present |
| `tartci owners dry-run [--json] [--scans N]` | read | per owner and repo, the queued jobs it would serve and the lane each maps to, the child VM size per OS, whether the forwarder login and the `gh-webhook` binary were found (never the token) and the forwarders it would run; mints and starts nothing. Exit 2 when a personal account is in `owners` or the config sets a removed key (`push`, `reconcile_seconds`, `poll_seconds`); exit 3 when a listing or scan failed |
| `tartci owners status [--json]` | read | the running dispatcher's repositories, children, child VM size, rate headroom and commit, discovery (scans by reason: `hint`, `guard`, `catchup`, `backlog`, `retry`, `recheck`, `discovery`, `relist`, `newly-served`; no polling interval or "next scan"), event counts, receiver rejections, the backlog and per forwarder its target, state (`starting`/`up`/`backing-off`/`stalled`/`stopped`), uptime or retry time, restarts, pid, hook id, last event, last catch-up and last error; every line it prints, `--json` too, has `gh[opsu]_…` tokens masked. Exit 1 when it is not running |
| `tartci owners run` | first takes an exclusive lock on `state/run.lock` (another `run` for the same root holds it: prints its pid, changes nothing, exit 3); refuses a missing forwarder login, a personal account in `owners` or a config that still sets `push`, `reconcile_seconds` or `poll_seconds` (all removed: nothing is polled) (exit 2; an owner of another account type is refused and logged DOWN), stops any forwarder a previous run left (recorded in `state/forwarders.json`, pid and start time matching), starts a receiver on `127.0.0.1` (`forwarder_port`, 0 = free) that accepts only POSTs to a forwarder's path with a valid `X-Hub-Signature-256` under a per-start random secret, at most 1 MiB, and never logs payloads, and supervises one `gh-webhook forward --events workflow_job` per organization in `owners` and per `repos` entry outside them, with the token from `forwarder_gh_config_dir/hosts.yml` passed only as `GH_TOKEN` (restart 5 s after an exit; 10/20/40/80/120 s backoff on 422, login errors or fast exits; deletes a stale hook after 60 s of 422 only if it recorded the id from that target's `ping` and its name is `cli`; one `ps` + one `lsof` every 20 s, restart on state T or twice CLOSE_WAIT/no ESTABLISHED; REST hook read every 30 min or on suspicion; a planned restart of each up forwarder every `rotate_seconds` (default 3600, staggered, 0 off) followed by its catch-up; kills every forwarder process group on exit). No REST call is made between triggers, even while children run, except the 30-minute hook read above and the bounded reap pass below. A `queued` event of a lane is only a hint: it triggers a scan of that repository; any `workflow_job` event (any action, any labels) of a repository with children triggers the fork-head guard for it (a scan of a served one, a runs re-read of an unserved one; only lane jobs start children); a forwarder's establish (startup, restart, rotation) triggers a catch-up scan of the repositories it covers and the guard of every repository with children; queued jobs left unserved are rescanned when a child exits, a backoff ends or admission reopens (checked locally every 10 s); a failed scan or guard reading is retried on the 10 s…5 min ladder; owners are fully re-listed at startup and on a catch-up when the last full listing is 15 min old (so about every `rotate_seconds`; with `rotate_seconds = 0` only when a forwarder re-establishes), and only the owner concerned on an unknown organization repository (at most every 60 s); a failed listing re-lists only what failed, on the 10 s…5 min ladder for no answer, a 5xx or a rate limit, at the next catch-up for a 4xx (e.g. SAML SSO), and a catch-up waiting for it runs only once it succeeds; a 404 on a run's jobs skips that run, a 404 on the repository or its runs unserves it and re-lists that repository once 60 s later (again 404: until the next full listing); a 401 on every scan of a cycle, a listing or `rate_limit` logs the login as DOWN at most every 10 min and never exits; the reap pass only visits repositories where a child failed in the last 3 h. Then it starts `tartci serve <os> --once` children (one per queued job, at most `max_jobs`, at most 2 macOS) for the private repositories in `~/.config/tartci/owners.toml`; mints JIT configs only through those children; its own `gh` calls run with the children's environment (keyring login, no `GH_TOKEN`/`GITHUB_TOKEN`) and a failing `gh auth status` is logged at startup; adopts its own children still alive after a restart (only when pid and recorded start time both match, whatever locale wrote the record; otherwise they are treated as ended and never signalled) and counts them against the caps; about every 90 s it also runs `scripts/vm_reap.py --runners-only --scopes repository --fix --repo R` for ONE repository where a child ended badly in the last 3 h (after a restart: whose children of the previous process are not recorded as ended cleanly; round-robin over those only, nothing otherwise — the one bounded exception to "no REST call between triggers"; skipped while R has a child of its own, while GitHub asked it to wait, after a scan failure, or below 25% rate headroom) with `--prefixes`/`--own-name-prefixes tartci-owners-,linux-ephr-`, a per-repository offline clock under `<root>/reap/` (its stdout digest goes to `logs/reap/last.json`, its stderr to `last.err`), the children's environment and the default 3 passes over 900 s: it reads and deletes repository-scope registrations only (the pool never registers at organization scope, so no `orgs/` or `users/` call is made) and only one that is offline and not busy, named like a per-boot runner of those prefixes (`linux-ephr-<pid>-<n>` is the name every tartci Linux lane uses, so another host's or lane's offline ghost for the same repository can match) and not carrying a `pulp-host-*` label, and it lists, stops and deletes no VM and reads no state file (`reap_leftovers` owns the pool's VMs) | pool not admitting (starts nothing). A repository that is archived, disabled, not admin, or whose settings cannot be read is dropped: no new runners start for it, and the runners already waiting expire on their own (they time out unassigned at ~120 s). A **security drop** (the repository is no longer private, "Run workflows from fork pull requests" is on or reads as on, or a run has a fork or unknown head repository) also stops its waiting runners immediately; a runner whose assignment was first seen within 15 s before the drop was detected is stopped too, because the assignment is seen up to ~6 s late (the runner polls its log every 5 s) and it may hold the job that made the repository unsafe — that is intended. On a fork-headed run the dispatcher also reads that run's jobs and stops any child holding one, assigned or not (all children of the repository if the jobs cannot be read, or if a fork job is running on a runner GitHub has not named yet). The fork-head guard does not end with the drop: for every repository that is not served (refused or dropped for any reason, or whose owner listing failed) but still has children, every scan cycle (whatever triggered it) re-reads its runs (also when they report a public repository) and stops a child holding a fork job, until those children are gone. A repository whose owner listing failed (rate limit, outage) is unknown, not refused: its waiting children are stopped, its assigned ones keep their jobs. An adopted child keeps the age of its assignment (its state file's mtime), so a restart does not make an old job look just assigned. Children get only an allowlisted environment (`PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `TMPDIR`, `TERM`, `GH_CONFIG_DIR`, `XDG_CONFIG_HOME`, `TARTCI_MACOS_VM_CAP`) plus what the dispatcher sets: no token, no `SSH_AUTH_SOCK`, no `LANG`/`LC_*`/`TZ` (so `ps -o lstart` renders the same for the child and for the dispatcher, which reads it under `LC_ALL=C` with no `TZ`, and nothing is sent into guests by ssh `SendEnv`), no inherited `TARTCI_*`/`PULP_*` (a child's VM size comes only from `owners.toml`'s `macos_vm_cores`/`macos_vm_mem_mb`/`linux_vm_cores`/`linux_vm_mem_mb`, passed as `TARTCI_{MACOS,LINUX}_VM_{CORES,MEM_MB}`; an unset key leaves the lane's own sizing: cores from the host profile, memory derived from the granted cores; an out-of-range value exits 2), and a pool-owned fetchcontent dir instead of `$HOME/Library/Caches/Pulp`. A tick that raises is logged, never fatal; a reap pass whose spawn raises waits a full interval before the next attempt. The dispatcher logs `spawn=disclaimed posix_spawn` or `spawn=Popen fallback` once at startup and `status` prints it (`child spawn:`); a failing disclaim call raises instead of starting a non-disclaimed child. Exit 75 after ~3 min of failed scans (a rate limit is not a failure; it is waited out), once no child remains; only failures with no answer or a 5xx count, of two distinct repositories in a row, of every served one, or of a scan and a listing, and only once `GET rate_limit` fails too (any answer below 500 clears it) |
| `tartci owners install [--rev REV] [--config PATH] [--dry-run]` | exports the commit `REV` (default `HEAD` of the checkout it runs from; under jj that is the parent of the working-copy change, so uncommitted edits are warned about and left out) with `git archive` to `~/.tartci/owners/app/<full sha>/` (0700, files read-only, `COMMIT` file), renders `launchd/com.danielraffel.tartci.owners.plist.template` into `~/Library/LaunchAgents/com.danielraffel.tartci.owners.plist` (0644) with absolute paths and the export's full-sha path (never `current`), boots out an old instance, waits until it is gone, replaces the plist, points `app/current` at the export (`app/previous` keeps the commit it replaced) and `launchctl bootstrap`s the new one; only after a successful bootstrap are older exports pruned, and never the one the installed plist runs. The agent runs `caffeinate -i /bin/bash <export>/tartci owners run` (RunAtLoad, KeepAlive, ExitTimeOut 210, logs `~/Library/Logs/tartci/owners.{out,err}.log`); no token is ever written. `--dry-run` prints the plist and the actions and changes nothing. Re-installing a commit that is already exported reuses its directory | the config is missing, does not parse or sets a removed key (`push`, `reconcile_seconds`, `poll_seconds`) (exit 2); the forwarder login (`forwarder_gh_config_dir/hosts.yml`) is missing (exit 2); `tart` or `gh` is not on PATH; `gh auth status` fails with `GH_TOKEN`/`GITHUB_TOKEN` scrubbed; the checkout has no `.git`; `REV` does not resolve, or its commit has no plist template; run as root; the old agent is still loaded after 240 s |
| `tartci owners uninstall [--purge]` | boots the agent out (SIGTERM: the dispatcher stops its forwarders and children and exits), waits for it, stops any recorded forwarder still alive (pid and start time matching), removes the plist, then reports any `tartci-owners-*` process or `tartci-owners-*` VM, or `linux-ephr-<pid>-<n>` VM whose `<pid>` is a child recorded in the pool's state, still present (exit 1; it deletes none, and never a golden, a base image or another lane's `linux-ephr-*` VM). Keeps `~/.tartci/owners` and the launchd logs. `--purge` also removes `app/`, `state/`, `logs/`, `reap/`, `cache/` and `fetchcontent-src/` under the pool root and `owners.*.log`, never the goldens, `owners.toml` or the VM key. `--purge` refuses a root that is `$HOME`, `~/.tartci`, outside `$HOME`, or has neither `state/dispatcher.json` nor `app/current` (checked before anything is stopped) | the agent is still loaded after 240 s (plist kept); `--purge` is skipped while leftovers remain |
| `tartci up <os>` | one build and test in a throwaway clone, then discards it | |
| `tartci prepare linux\|macos`, `tartci windows golden` | bakes a golden image | |
| `tartci goldens sync --to HOST\|--from HOST` | copies the Windows golden between hosts, verifies, repoints | |
| `tartci tart-image-sync` | resumable, checksum-verified Tart image transfer | |
| `tartci doctor --reap --fix` | deletes owned stale residue (see invariants) | |
| `tartci reclaim --fix`, `image-prune --apply`, `retention --apply` | deletes idle build dirs, unreferenced images, old state | |
| `tartci reclaim --on-lease-denial --fix` | evicts gate ccache entries unused for 14 days and deletes OCI cache images nothing references (the step a lane runs by itself on a disk-refused lease); never a local VM, worktree or checkout | cooldown (30 min per host), another lane running it, a VM running or leased (ccache only), a `tart pull`/`clone` running (OCI only) |
| `tartci ccache quarantine`, `ccache reset` | moves suspect manifests aside; resets a cache | reset: a VM runs or holds a lease (exit 3) |
| `tartci held stop\|delete\|expire\|inspect NAME` | manages failed gate VMs kept for debugging | inspect: no free slot |
| `tartci fleet-macos install CONFIG` | installs generated fleet lanes | |

## Guard

| command | effect |
|---|---|
| `tartci launchd guard --hook` | PreToolUse classifier for agent shells. Exit 2 blocks raw `launchctl kickstart\|bootout\|unload\|remove\|kill\|disable\|stop` against a tartci lane or `actions.runner.*` service, and broad process kills. `TARTCI_ALLOW_RAW_LAUNCHCTL=1` written in the command is the audited escape |
